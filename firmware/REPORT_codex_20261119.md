## Changes and reasons

1. Corrected version parsing so the `2000` in `C2000_22.6.2` is not mistaken for the version. This removed false compiler disagreements.
2. Inventoried both `.metadata/product.json` and `.metadata/sdk.json`, including nested/bundled products and top-level folder versions. This supplies C2000Ware/powerSUITE facts without product-specific hard-coding.
3. Matched include and SysConfig product paths to the most specific installed SDK component, preserved missing Windows/old-SDK paths, and reports both product and enclosing-folder versions. Every repeated SysConfig `-s` and `--script` argument is retained.
4. Added per-build mtime checks, exact `STALE` and `ASK USER` output, and return code 3 for stale or never-built selected configurations.
5. Added linker archive/search-path/linker-script extraction. A map file is authoritative; otherwise the linker recipe is used. Resolution is classified as project, SDK, other (normally compiler/toolchain), or unresolved.
6. Extended `sdk_inventory --match` with device/part-number words and the missing SDK/compiler/SysConfig/device questions.
7. Added sibling related-project facts with device/core IDs from each `.cproject`; the output makes no flashing recommendation.
8. Added standard-library tests in `test_sdk_inventory.py` and `test_project_facts.py`.
9. Rule discovery now follows only the `-include .../subdir_rules.mk` paths in each build makefile. It falls back to recursive discovery only when the makefile declares no rule files, and the manifest labels the selection mode and count.
10. Added injected-host OS classification for compiler, SysConfig, and SDK recipe paths. Foreign builds print `FOREIGN`, ask for a rebuild on this machine, and return 3.
11. Versions are extracted from both POSIX and Windows-style path names. Foreign items report an installed local compiler/SysConfig/SDK of the same kind and exact version, or `none installed`, without changing the recipe.
